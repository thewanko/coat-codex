## 2026-11-03 typecheck-gate 模擬入力でしか試していないゲートを、効く前提で文書に書いていた [BAD]

- 事象: impl の終了時に型エラーで差し戻す hook を、模擬入力のテストだけで「1回だけ差し戻す」と skill に書いた。本物の impl で試すと、hook は exit 2 を返すのに impl は先に報告（SubagentHandback）を返して終了しており、差し戻しは届かなかった（フロントマターと settings.json の SubagentStop の両方で同じ）。計測用の trap で `$?` の前に `$(date)` を展開し、exit 2 を 0 と誤記録して遠回りもした。
- 原因: ゲートの効き目を本物の実行経路で確かめる前に、仕組みとして文書へ書いた。ドキュメントのライフサイクル（Stop の exit 2 で差し戻し）がこのアプリのバックグラウンド起動でも成り立つと仮定した。
- 一般化ルール: ハーネスのゲートは、本物の実行経路で意図的なエラーを入れて止まることを確かめてから完成とする。計測では `$?` を最初に変数へ退避する。
- 反映先: `goal-loop` skill の「出口ゲート」（1件目「全体を検査するゲートはエラーを入れて確かめる」と同じ根本原因の2回目として昇格）

## 2026-11-03 citadel-tone-pro Web の要約経由で得た150件の hex を、原文 HTML とスクリプトで全件照合してから取り込んだ [GOOD]

- 事象: トーンプロの hex を WebFetch の要約で集めたが、取り込む前に `curl` で原文の HTML を取得し、表をパースして下書きと150件を突き合わせた（全件一致）。既存334件の不変も、HEAD の JSON と配列比較で確かめた。

- 発生回数: 1回目
